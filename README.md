# Start here

New to ALFA, or opening one of our builds for the first time? You do not need to
know how any of this works. You need one line.

Open the repo you want to try, then paste this to Claude:

> Claude, clone this repo, tell me what it does, and set it up so I can use it.

That is it. Claude reads the project, explains it in plain language, and walks you
through setup one step at a time.

## What to expect

- A plain-language summary of what the tool does and does not do.
- The setup steps for your machine, one at a time.
- A place to ask questions as you go. If something is unclear, ask Claude to slow
  down or explain it a different way.

## A note on client data

Many ALFA builds run locally so your data stays on your machine. Before you put any
real client information into a tool, confirm where that data goes. When in doubt,
use sample or anonymized data first. The licensed practitioner reviews, decides,
and signs.

## Built something?

ALFA members can share their own repos in the ALFA GitHub, where every member can see
them, adapt them, and send improvements. They stay private to ALFA.

1. Check it first: no passwords, API keys, tokens or `.env` files anywhere in the repo
   or its history, and no client data, even in test files.
2. Add a README that says what it does, how to set it up, what it can read or change,
   and the compliance notes a firm needs before running it on client work.
3. Create a private repo with AI-Lab-for-Accountants as the owner, or transfer yours in.
4. Share it as a build on the site so members can find it.

The full steps are on the ALFA GitHub page in the Library on ailabforaccountants.com.
